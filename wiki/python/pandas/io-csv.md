# wiki: pandas — чтение и запись CSV (v1)

Сценарий для узла «исполнитель»: read_csv / to_csv. Все примеры привязаны к pandas 3.0.3.

## dtype — явный контроль типов
- **GOOD:** `pd.read_csv(path, dtype={"qty": "Int64"})` — поведение не зависит от данных.
- **BAD:** `pd.read_csv(path)` без dtype — тип колонки определяется содержимым и может меняться.
- **Когда избыточен:** если все колонки заведомо имеют стабильные типы (например, только строки) и автоматическое определение устраивает — можно опустить, но это риск.

## parse_dates + date_format
- **GOOD:** `pd.read_csv(path, parse_dates=["date"], date_format="%Y-%m-%d")`
  infer_datetime_format удалён; явный формат для ISO8601 даёт быстрый путь (~20x).
- **BAD:** полагаться на автоматическое угадывание даты без date_format.
- **Когда избыточен:** если колонка с датами не нужна как datetime — не парси.

## usecols — парсить только нужное
- **GOOD:** `pd.read_csv(path, usecols=["id", "amount"])` — меньше памяти, быстрее разбор.
- **Избыточен, когда нужны все колонки:** не добавляй usecols ради явности — CSV-парсер читает всё, overhead минимален.

## na_values — полный контроль пропусков
- **GOOD:** `pd.read_csv(path, na_values=["\\N"], keep_default_na=False)` — строго один маркер; дефолтные ("NA", "NULL", "None", "" и пр.) отключены.
- **BAD:** не учитывать, что "NA" по умолчанию считается пропуском, и получить потерю валидных текстовых меток.
- **Когда избыточен:** если дефолтный список устраивает и данных с коллизиями нет.

## chunksize — большие файлы
- **GOOD:** `with pd.read_csv(path, chunksize=100_000) as reader: for chunk in reader: process(chunk)`
- **BAD:** читать файл целиком, когда он не помещается в память.
- **Избыточен, если файл свободно помещается в память:** лишнее усложнение.

## to_csv — запись без индекса
- **GOOD:** `df.to_csv(path, index=False)` — индекс в CSV почти никогда не нужен.
- **BAD:** to_csv() по умолчанию пишет индекс; при повторном чтении получается лишний столбец Unnamed: 0.
