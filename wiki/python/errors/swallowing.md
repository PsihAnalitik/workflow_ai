# wiki: каталог проглатывания исключений (v1)

Словарь ревьюера: паттерны, при которых исключение перехвачено, но ни
обработано осмысленно, ни переброшено с контекстом. Вес — по шкале
🔴p3 🟠p2 🟡p1 🟢p0; сомнение между двумя весами → МЕНЬШИЙ.

## Паттерны

- **S1 🔴p3 — голый `except:`.** Ловит и `SystemExit`/`KeyboardInterrupt`.
  Всегда находка, даже с re-raise внутри: минимум `except Exception:`.
- **S2 🔴p3 — перехват в никуда.** `except ...: pass` / только `log` /
  только `print`, при этом вызывающий ждёт результат или побочный эффект.
  Ошибка исчезает, программа продолжает жить в неконсистентном состоянии.
- **S3 🟠p2 — широкий перехват вместо конкретного.** `except Exception:`
  там, где точка риска известна (`FileNotFoundError`, `KeyError`,
  `json.JSONDecodeError`…). Прячет неожиданные баги под видом ожидаемых.
- **S4 🟠p2 — потеря причины.** `raise NewError(...)` внутри `except`
  без `from e`: traceback исходной ошибки оторван (`__cause__` пуст).
- **S5 🔴p3 — подмена значением.** `return None` / пустая коллекция /
  дефолт из `except`, когда контракт функции этого не объявляет: ошибка
  превращается в «нормальные» данные и уезжает дальше по пайплайну.
  🟡p1, если дефолт объявлен контрактом (docstring/аннотация/имя).
- **S6 🔴p3 — `__exit__`/`__aexit__` возвращает True** (или truthy) без
  комментария намерения: context manager молча глотает ВСЕ исключения блока.
- **S7 🟠p2 — `finally`/`__exit__` поднимает своё исключение**, затирающее
  исходное (например, `close()` без защиты внутри `finally`).
- **S8 🟠p2 — `except` + `continue` в цикле** без учёта ошибки: обработка
  элементов «сжирает» сбои, итог выглядит полным, хотя часть элементов
  потеряна (нет счётчика/агрегации ошибок/итогового отчёта).

## НЕ находка

- Подавление узкого типа с комментарием намерения и, где уместно,
  логированием: `contextlib.suppress(FileNotFoundError)` при удалении
  temp-файла, `except QueueEmpty: pass` в poll-цикле.
- `except Exception` на ВНЕШНЕЙ границе процесса (main, handler запроса,
  воркер очереди) с логированием и осмысленным ответом/кодом выхода —
  граничный барьер, а не проглатывание.
- Re-raise как есть (`raise`) после логирования/метрик.
- Fallback на последней попытке retry-политики, если fallback объявлен
  (см. Т4 в [handling.md](handling.md)).
