# wiki: Django (v1)

> ⚠ unverified: написано из знаний модели без внешнего материала — проверь факты при приёмке.

## Когда использовать
- Серверный рендеринг HTML с формами и аутентификацией (витрины, дашборды, админки).
- Проекты с реляционной БД, где нужны миграции и админ-панель из коробки.
- Быстрая разработка прототипов с автоматической админкой.

## Когда НЕ использовать
- SPA с JSON API и раздельным фронтендом — бери FastAPI (меньше оверхеда).
- Высоконагруженные real-time сервисы (WebSockets) без доработок — Django Channels добавляет сложность.
- Микросервисы без ORM и шаблонов — фреймворк избыточен.

## Архитектура проекта
Проект Django 5.x состоит из:
- **settings.py** — конфигурация БД, статики, middleware, установленных приложений.
- **apps** — модули с моделями, представлениями, шаблонами и статикой.
- **models.py** — ORM-модели, поля, связи, менеджеры.
- **views.py** — функции (FBV) или классы (CBV), возвращающие HTTP-ответ.
- **urls.py** — маршруты: path/re_path, именованные маршруты, include.
- **templates/** — HTML-шаблоны с наследованием и тегами.
- **static/** и **media/** — CSS/JS/изображения и загружаемые пользователем файлы.

## Скоуп витрины (frontend_site)
Для витрины портфолио-платформы актуальны:
- templates + views + ORM (без DRF).
- static/media для ресурсов.
- HTMX и Alpine.js поверх шаблонов (см. [templates](templates.md)).

## Вне скоупа
- Django REST Framework (DRF) — не нужен для серверного рендеринга.
- Celery/фоновая очередь — витрина синхронна.
- Глубокая кастомизация админки — достаточно стандартной.
