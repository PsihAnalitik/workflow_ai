# wiki: rework-цикл (v1)

Механика адресной доработки артефактов по находкам ревьюера. Проблема,
которую решает: на повторной итерации генератор не видел свой предыдущий
артефакт — получал только текст находок — и перегенерировал с нуля, внося
новые дефекты. Цикл расходился (3+ итерации). Решение: вариант B — передача
целого артефакта + якорных находок.

## Формат iteration_context

Генератор на итерации N≥2 получает в промпте блок `<iteration_context>`:

- **Полный черновик предыдущей итерации** — артефакт как он был принят/отклонён.
- **Находки ревьюера** — каждая с якорем по стабильному id артефакта:
  `<finding id="F-01" … anchor="MOD-01">`.

Якорь — это id элемента внутри артефакта: `G-NN` (цель), `FR-NN` (требование),
`MOD-NN` (модуль). Система id — фундамент методологии (NFR-02); упоминание id
в находке активирует внимание модели к блоку с этим id (приём из practices:
перекрёстные ссылки по имени).

## Почему не вариант A (inline-комментарии)

Inline-комментарии в теле артефакта (XML-комментарий рядом с дефектом) ломают
структуру: парсер артефакта должен уметь отделять комментарии ревьюера от
содержимого; модель может принять их за часть артефакта. Вариант B чище:
артефакт untouched + отдельный блок находок.

## Результат

Живой smoke на deepseek (data_analyst, чистый стор):

- Итерация 1 — генерация без rework-контекста. Ревьюер: одна находка с якорем
  `anchor="MOD-01"`, severity p2.
- Итерация 2 — в `<iteration_context>` черновик v1 + `<finding anchor="MOD-01">`.
  Генератор явно пишет «модифицирую MOD-01 согласно находке F-01».
  Ревьюер: PASS.
- **task_spec сошёлся за 2 итерации** — против расходимости за 3+ без
  rework-контекста.

Дальше: `tech_selection → executor → judge READY` без замечаний.

## Применимость

Механика работает для всех workshop-узлов. Для codegen-узлов — отдельная
доработка: внутренний тест-цикл и judge NOT_READY также получили
`<previous_artifact>` (file map) + вердикт/тест-репорт (задача 10, контракты
TSK-1101/TSK-0901).
