# wiki: динамические wiki_refs (v1)

Механика автоматической подстановки актуальных wiki-страниц в контекст
цеха `wiki_maintainer` — генератор и ревьюер получают страницы без
передачи текста в запросе пользователем.

## проблема

До v5: `wiki_pages` цеха имели только статические `wiki_refs` —
захардкоженные ссылки на страницы методологии. При обновлении страницы
через `wiki_change` текущий текст нужно было передавать в материале
вручную.

## решение: parse_wiki_refs_source

Обобщённый парсер `parse_wiki_refs_source` (TSK-1604) понимает два
формата источника:

| Источник | Формат | Что извлекает |
|---|---|---|
| `tech_stack` | `<tech ref="…"/>` | страницы технологий |
| `wiki_change` | `<page path="…" action="update">` | update-страницы из принятой спеки |

**Инжектятся только update-страницы** — add-страниц ещё не существует
в вики на момент генерации. Спека из одних add — легально пустой
список динамических ссылок.

Ошибка парсинга: `WIKI_REFS_SOURCE_UNPARSEABLE`.

## Union вместо XOR

Ранее `wiki_refs` (статические) и `wiki_refs_from` (динамические)
были взаимоисключающими (XOR-валидация). Теперь сосуществуют —
динамические ссылки **добавляются** к статическим.

Пример: у `wiki_pages` есть постоянная методология прожарки
(статические) + индексируемые страницы из принятой спеки (динамические).

## как работает в прогоне

1. Цех `wiki_maintainer` получает на вход `wiki_spec` и `wiki_change`
2. `parse_wiki_refs_source` извлекает пути update-страниц из `wiki_change`
3. Перед вызовом генератора и ревьюера конвейер читает актуальные
   страницы из вики и подставляет в контекст
4. Пользователь передаёт только суть правки и новый материал —
   **текущий текст страниц не нужно дублировать в запросе**
