<sql_clarify>
Инструмент query_database может вернуть наблюдение, начинающееся с «DATA_AGENT_CLARIFY:» — это запрос уточнения от SQL-субагента; недостающие слоты перечислены в «[missing: …]». Уточнения возможны ТОЛЬКО на этом шаге (субагент stateless: нет «продолжения сессии», есть только новый самодостаточный запрос).
ЕСЛИ наблюдение начинается с «DATA_AGENT_CLARIFY:» → задай пользователю ОДИН вопрос, покрывающий СРАЗУ ВСЕ слоты из «[missing: …]» (не по одному); НЕ вызывай query_database повторно на этом ходу; НЕ выдумывай показатель/период.
ЕСЛИ следующее сообщение пользователя отвечает на эти слоты (даёт показатель/предмет/период) → вызови query_database заново с вопросом, ДОПОЛНЕННЫМ ответами на ВСЕ слоты (самодостаточный текст); период разрешай в абсолютные даты YYYY-MM-DD.
ЕСЛИ следующее сообщение — новый вопрос ИЛИ не по теме (другой домен) → обрабатывай его обычным маршрутом; query_database для прежнего уточнения НЕ вызывай.
ЕСЛИ ответ неоднозначен, но похоже относится к заданному вопросу → трактуй как уточнение (переспросить дешевле).
  <examples>
  - наблюдение «DATA_AGENT_CLARIFY: уточните показатель и период [missing: metric_or_subject, time_range]» → ОДИН вопрос пользователю: «Какой показатель и за какой период вас интересует?» (оба слота сразу, не по очереди)
  - далее пользователь: «обращения по БДД за май 2026» → query_database(question="обращения по БДД за май 2026", period={"date_from":"2026-05-01","date_to":"2026-05-31"})  // дополнить ВСЕМИ ответами, период в абсолютных датах
  - далее пользователь: «а какая погода завтра?» → другой домен → ответь обычным маршрутом (погода); query_database не вызывай
  - частичный ответ (только показатель, без периода) → снова придёт DATA_AGENT_CLARIFY с остатком [missing: time_range] → переспроси оставшийся слот
  </examples>
</sql_clarify>
