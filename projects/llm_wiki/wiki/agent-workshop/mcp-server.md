# wiki: MCP-сервер agent-workshop (v1)

MCP-сервер фабрики предоставляет 12 инструментов для управления цехами
и конвейерами из Claude Code. Реализован на официальном SDK `mcp`
(решение №15), 212 тестов зелёные.

## инструменты

| Инструмент | Назначение |
|---|---|
| `list_shops` | список цехов с конвейерами |
| `run_shop` | асинхронный запуск прогона; возвращает `run_id`; ≤1 живого прогона на project |
| `run_status` | статус прогона; для живых статусов показывает `(узел X, итерация N)` |
| `get_pending_interaction` | получить HITL-гейт: отчёт ревью + артефакт или вопрос |
| `submit_decision` | решение по гейту: `accept` / `revise` / `reject` |
| `wiki_read` | чтение wiki-страницы по относительному пути; защита `WIKI_REF_ESCAPES_ROOT` — выход за корень wiki отклоняется |
| `project_status` | состояние проекта (стор, активные прогоны) |

Остальные 5 инструментов — вспомогательные (управление материалом,
журналы, административные).

## HITL-протокол

Асинхронный run_shop с гейтами на узлах, требующих решения человека
(Human-In-The-Loop). Реализован через `RunManager` + `_QueueHITL`
(TSK-2001, протокол M-08).

Сквозной сценарий дистанционного HITL:
1. `list_shops` → выбор цеха
2. `run_shop(shop, material, interactive)` → `run_id`
3. поллинг `run_status` до статуса `awaiting_decision`
4. `get_pending_interaction` → отчёт + артефакт
5. `submit_decision(accept|revise|reject)` → продолжение прогона
6. финальный `run_status` → результат

## статусы прогона

| Статус | Смысл |
|---|---|
| `running` / `awaiting_*` | живые статусы с прогрессом узла |
| `completed` | успешное завершение |
| `rejected` | пользователь отклонил через HITL — **не сбой**, нормальное завершение |
| `failed` | ошибка исполнения |

`rejected` — отдельный терминальный статус (ранее `REJECTED_BY_USER`
попадал в `failed`, что вводило клиентскую LLM в заблуждение).

## прогресс узла

`run_status` для живых прогонов возвращает `(узел X, итерация N)`.
Реализовано без правок оркестратора: `RunManager` запоминает размер
журнала на старте и читает только хвост своего прогона.

## безопасность

- `wiki_read` проверяет путь: выход за корень wiki (`../.env` или
  абсолютные пути) → отказ с `WIKI_REF_ESCAPES_ROOT`
- `run_shop`: ≤1 живого прогона на project — защита от повторного
  запуска поверх незавершённого

## подключение к Claude Code

```bash
claude mcp add workshop -- python -m workshop mcp-serve
```

Сервер работает через stdio-транспорт SDK. Проверен живым сквозным
сценарием: вложенный Claude Code выполнил полный цикл `list_shops →
run_shop → поллинг → get_pending_interaction → reject → rejected`.

## известные риски

- **Синхронный `wiki_update`** — риск таймаута клиента на длинных
  прогонах цеха `wiki_maintainer` (наблюдение, не блокирует)
