# wiki: web-search (v1)

Инструмент `web_search` для LLM-агентов в цехах фабрики.
Реализован на сессии a06a07b9 (2026-07-10) через GRACE-цикл:
DevelopmentPlan → MENTAL_TEST → код.

## Архитектура

- **Модуль M-21** `workshop/web_search.py` — клиент Tavily API
  (TSK-2101). Поисковый бэкенд: Tavily, ключ `TAVILY_API_KEY`
  из `.env`.
- **`workshop/llm_client.py`** — `ToolSpec` (имя + JSON-схема +
  исполнитель), поле `LLMResponse.tool_trace`, расширенная
  сигнатура `complete(prompt, params, tools)`. Провайдер:
  deepseek-v4-pro через openai-совместимый function calling.
- **Tool-цикл** (TSK-0402 в M-04): модель вызывает инструмент,
  исполнитель возвращает результат текстом, модель продолжает
  ответ. Адаптер реализован в `llm_client.py`.
- **Реестр инструментов** — поле `NodeConfig.tools` (TSK-2102),
  в конфиге узла: `"tools": ["web_search"]`.

## Принудительный финал после 5 раундов

Проблема: deepseek при неидеальных сниппетах бесконечно уточнял
запрос и выжигал лимит раундов, роняя узел с `TOOL_LOOP_EXCEEDED`.
Решение: после 5 раундов — принудительный финал, модель обязана
ответить из накопленных результатов. Если провайдер игнорирует и
это — ошибка с трейсом вызовов в `details`.

## Интеграция с wiki_spec

Узел `wiki_spec` получил `web_search` (tools + правило в промпт):
только точечная проверка фактов (существование технологии,
стабильная версия, имя пакета), 1–2 запроса, не исследование.
Поиск не заменяет материал — политика `unverified` определяется
наличием материала в запросе, а не результатами поиска.
