# wiki: python/polars (v1)

> ⚠ unverified: написано из знаний модели без внешнего материала — проверь факты при приёмке. Стабильная версия ~1.42.1 (уточни по PyPI).

Polars — многопоточная DataFrame-библиотека на Rust с ядром Apache Arrow и ленивыми вычислениями (lazy evaluation). API основан на выражениях (expressions), а не на inplace-мутациях.

## Когда использовать
- **Большие датасеты (> памяти):** streaming + lazy evaluation позволяет обрабатывать данные, не загружая весь DataFrame в RAM.
- **Требовательность к latency:** многопоточная обработка на всех ядрах CPU; бенчмарки показывают значительное ускорение по сравнению с pandas на тяжёлых агрегатах.
- **Длинные цепочки преобразований:** ленивый план строится и оптимизируется до исполнения, исключая промежуточные материализации.

## Когда НЕ использовать
- **Интерактивная разработка с частым просмотром промежуточных данных:** каждое ленивое вычисление требует `.collect()`, что добавляет трение; pandas позволяет быстро осмотреть DataFrame в REPL.
- **Код, где pandas уже стабильно работает и производительность не критична:** миграция несёт риски регрессии API ради преждевременной оптимизации.
- **Экосистемная зависимость:** библиотеки, ожидающие `pandas.DataFrame` (многие ML-фреймворки, plotly, стиль кода сообщества), не примут `polars.DataFrame` без конвертации.

## Good vs Bad

**Bad** — использовать polars для простой фильтрации 100 строк из CSV, когда весь проект уже написан на pandas и тесты завязаны на `pd.DataFrame`:
```python
import polars as pl
df = pl.read_csv("small.csv").filter(pl.col("amount") > 0).collect()
# результат конвертируют обратно в pandas для sklearn — двойная конвертация.
```

**Good** — ленивая обработка большого CSV с фильтрацией, группировкой и агрегацией; потоковое исполнение без загрузки всего файла:
```python
import polars as pl
q = (
    pl.scan_csv("large.csv")
    .filter(pl.col("status") == "done")
    .group_by("category")
    .agg(pl.count())
)
# .collect(streaming=True) — только на финальном шаге.
df = q.collect()
```

**Bad** — использование `.with_columns` в цикле с накоплением ленивого плана без явного `.collect()`, приводящее к десяткам вложенных узлов и замедлению планировщика.
