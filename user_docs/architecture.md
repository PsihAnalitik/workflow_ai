Делаю инфраструктуру для агентной разработки по своей методологии.

Что нужно?

Генерация артефактов:
1. построить граф состояний на каждом из узлов которого агенту подается только конкретная информация и инструменты (релевантная на этом этапе): например, на этапе 
описания пользовательских требований (ФТ / НФТ) подается только промпт, wiki, шаблоны и few-shots positive/negative examples по конкретно ФТ / НФТ.
2. Добавить "инъектируемые" узлы графа, на которых:
    - пользователь может делать Review артефакта: пайплайн выдачи замечаний / комментариев / открытых вопросов / предложений и т.д. [для любого артефакта]
    - Агент делает Review артефакта: подается на вход domain_context, артефакт, правила Review [что проверяем и как], tools для review.


Мастерская:

1. На вход подается готовый (сгенерированный) артефакт уровня C4: с указанием технологического стека, конкретных алгоритмов реализации, шаблоны, примеры (позитив негатив)
2. агент который пишет код по заданным артефактам: 
    - пишет по независимым модулям (независимые в смысле тестирования - каждый объект кода можно отдельно протестировать)
    - оформляет тесты под написанный объект: проверка что модуль работает РОВНО ТАК, как задумывалось
    - запуск кода в виртуальной среде [песочнице]
    - анализ результатов / улучшение кода.
3. Тестировщик: агент который проверяет пользовательские сценарии разработанного сервиса, краевые случаи вопросов, ошибки в контрактах, ФТ / НФТ и т.д.
4. Judge: вердикт о готовности сервиса.
5. User review: разработчик сам тестирует сервис "как пользователь".
