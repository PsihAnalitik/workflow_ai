# wiki: map-driver (v1)

M-23 map-драйвер — механизм пакетного прогона цеха фабрики по списку независимых
элементов. Каждый элемент — полноценный прогон со своим под-стором и журналом
в `projects/<project>/map/<slug>/`; падение одного элемента не останавливает
остальные.

## CLI

```bash
python -m workshop map <цех> --files 'glob'       # промпты/файлы
python -m workshop map <цех> --schema-tables schema.yaml --table-cards <dir>
```

## Ключевые механики

- **`--resume`:** пропускает элементы с принятым артефактом v1 в под-сторе —
  перезапускаются только упавшие.
- **`--workers N`:** параллельный прогон через пул потоков (потолок 16,
  дефолт 1 — поведение без флага не меняется). Потоки, а не asyncio/процессы:
  LLM-вызовы — это десятки секунд HTTP-ожидания, GIL не мешает; элементы
  изолированы по сторам и журналам. `pool.map` сохраняет порядок подачи
  элементов, поэтому сводка детерминирована.
- **`map/summary.md`:** агрегат по всем элементам после завершения цикла —
  оркестратор выводит строки разом по окончании map-прогона.

## Ограничения HITL

Граф с HITL-гейтами + `workers>1` → явный отказ `MAP_PARALLEL_HITL` до единого
прогона. Интерактивные цеха под параллельный map не пускаются — только
полностью автоматические.

## Уроки внедрения

- **Результат прогона 26 промптов:** 4 упали в первом прогоне (зацикливание на
  R3 без негативного случая, один таймаут на большом файле); `--resume` добил
  хвост.
- **Результат прогона 53 таблиц:** 7 упали при первом запуске; те же 7 —
  после `--resume` с 4 воркерами (~25 минут вместо ~100). На одном элементе
  поймали зацикливание ревью — правило V3 было без белого списка локаций.
