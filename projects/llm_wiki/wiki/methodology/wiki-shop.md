# wiki: цех wiki_maintainer (v1)

Цех автоматической актуализации wiki-базы знаний. Пайплайн: пользователь
подаёт материал → цех генерирует спецификацию изменений → страницы →
применяет через детерминированный applier. FR-21.

## Пайплайн

```
wiki_change_spec (v1) → wiki_pages (v1) → wiki-apply (M-18)
```

- **wiki_change_spec** — стадия анализирует поданный материал и формирует
  `wiki_change_spec.xml`: какие страницы создать/обновить, source_chunks,
  index_row для каждой, related-ссылки.
- **wiki_pages** — стадия пишет содержимое страниц согласно спеке, читая
  указанные source_chunks через material_get.
- **wiki-apply** (M-18) — детерминированный applier: накладывает изменения на
  временную копию wiki, прогоняет проверки (индексы, перекрёстные ссылки,
  двойные фигурные скобки, сироты), и только при чистом контуре атомарно
  записывает в настоящую wiki.

## Приёмка (FR-17)

Каждое изменение wiki трассируется: запись в `wiki/CHANGELOG.md` с sha256-хэшами
изменённых файлов, версией прогона (v1→v1), результатами гейтов (PASS/FAIL).
Контроль: `verify-acceptance wiki/` проверяет актуальность приёмки,
`wiki-check` — структурную целостность.

## Формат wiki_change_spec.xml

Спецификация содержит:

- `<summary>` — что меняется.
- `<pages>` — список страниц: `path`, `action` (add/update), `unverified`,
  `source_chunks` (id чанков), `index_row`, `related`.
- `<index_updates>` — какие index.md затронуты.
- `<backlog>` — что осознанно отложено.

## Dogfooding-опыт

Цех применялся к собственной wiki трижды. Каждый прогон выявил реальные дефекты
защитных слоёв:

1. **Инъекция управляющего маркера**: слово `NEEDS_CLARIFICATION` в данных
   запроса срабатывало как протокольный маркер — узел уходил в ложный
   clarification. Исправлено: порядок парсинга (блок артефакта раньше маркера).
2. **Конвенция-разрыв ревьюера**: review-узел на deepseek не следовал формату
   из-за нехватки токенов контекста.
3. **Вложенные fenced-блоки**: парсер file map ломался на ``` внутри ```.
   Каждый дефект пойман своим слоем и исправлен до применения.

Результат: страница `methodology/workshop-cli.md` добавлена самим цехом —
полный справочник CLI с 11 подкомандами, все факты из поданного материала.

## Правило для оператора

Успешный прогон `wiki_maintainer` → сразу `wiki-apply` + запись в
`wiki/CHANGELOG.md`, без отдельного вопроса.
