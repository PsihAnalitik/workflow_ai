# wiki: prompt-roasting (v1)

Методология прожарки промптов (П1–П8) — процедура поиска системных дефектов
в промптах агентных узлов. Реализована цехом `prompt_roaster`, зашита в
wiki фабрики (`wiki/agents/prompts/review.md`): severity и формат находок
заточены под парсер гейта.

## Измерения П1–П8

Каждое измерение — класс дефектов, по которому модель выносит находки p2/p3:

| Изм. | Суть |
|---|---|
| П1 | Неоднозначность инструкций |
| П2 | Противоречия между секциями |
| П3 | Перегрузка правилами (curse of instructions) |
| П4 | Пользовательский ввод размещён до правил/safety-секций |
| П5 | … |
| П8 | Неэкранированный ввод, интерпретируемый как данные |

## Результаты прогона 26 промптов стороннего проекта

**22 из 26 FAIL, 64 находки p3.** Три системные болезни покрывают почти все:

1. **П3 — перегрузка правилами (23 находки):** блоки генерации несут по 5–16
   активных правил при практическом пределе ~4 (соблюдение ≈ p^n).
   Рекордсмены — `CLASSIFIER_PROMPT` (~16 правил на один JSON-вывод) и
   `FINAL_ANSWER_PROMPT` (11 p2). Лечится разбиением на фазы/цепочки узлов.
2. **П4 — ввод раньше правил (18):** пользовательский вопрос размещён до
   правил и safety-секций — из-за causal attention токены ввода «не видят»
   защиту. Лечится перестановкой секций: правила и safety перед вводом.
3. **П8 — неэкранированный ввод (17):** текст пользователя подаётся как
   данные без экранирования — риск injection. Лечится оборачиванием в
   маркерные токены/XML-теги.

## Техническая деталь

**15 из 26 промптов содержат литерал двойных фигурных скобок** — их нельзя
вставлять в INPUTS инлайном: `prompt_builder.assemble` упадёт на
leftover-проверке плейсхолдеров. Текст промпта подаётся в модель только
через `material_get` — результаты tool-вызовов идут в messages мимо шаблона.

## Урок

R3-правило ревью без негативного случая привело к зацикливанию на 4 промптах;
добавлен негативный пример, прожарщик научен оформлять фрагменты — хвост добит
с `--resume`.
