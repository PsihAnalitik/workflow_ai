# wiki: правило достижимости (v3)

Главный механизм подавления ложных срабатываний в цехе `code_auditor`.
Модель склонна предполагать у атакующего возможности, которых у него нет:
читает опасный вызов и достраивает вокруг него сценарий, не проверяя, дойдёт
ли туда внешний ввод вообще.

**Правило.** Находка без выписанного пути от недоверенного входа до уязвимой
строки понижается до 🟢p3 — «отмечено, не доказано». Понижение
автоматическое: отсутствие пути не обсуждается и не компенсируется
убедительностью формулировки.

## Что считается недоверенным входом

- Тело, заголовки, cookies, query и путь HTTP-запроса; поля формы.
- Загруженный файл и его имя; содержимое архива.
- Сообщение очереди, вебхук, callback стороннего сервиса.
- Данные из БД, записанные пользователем ранее (second-order).
- Переменные окружения и аргументы CLI — ТОЛЬКО если процесс запускается
  недоверенной стороной (обычно нет).

Не является недоверенным входом: константы модуля, собственный конфиг
развёртывания, значения из кода тестов, аргументы, которые может задать
только администратор хоста.

## Элемент без внешнего периметра

Не у всякого кода есть недоверенный вход. CLI-утилита, библиотека,
внутренний модуль пакета получают значения из конфига, от вызывающего кода
и из аргументов функций — ни то, ни другое, ни третье недоверенным входом
не является.

**Правило.** ЕСЛИ в элементе не найдено НИ ОДНОЙ точки входа из списка выше →
все находки элемента идут 🟢p3 с основанием A, и это нормальный результат
аудита, а не признак поверхностной работы.

**Запрет достраивания.** Точка входа, которой нет в самом элементе, не
предполагается. Формулировки вида «(внешний HTTP-обработчик) → …»,
«если этот модуль вызвать из веб-приложения», «злоумышленник может передать»
без указания места, откуда значение приходит, — это выдуманное звено:
находка с таким путём идёт 🟢p3, а сам факт достраивания отмечается в
обосновании. Параметр публичной функции — не точка входа, а середина пути;
началом он становится, только если в элементе видно, кто его вызывает
с внешним значением.

**Условие применимости классов.** Классы C11 (авторизация) и C12
(потребление ресурсов) осмысленны только для элемента с сетевым периметром:
в CLI-утилите нет ни чужого пользователя, чьи права нарушаются, ни
атакующего, задающего размер входа. Без периметра они не выставляются вовсе.

Дискриминатор для сомнительного случая: назови конкретный процесс, который
принимает значение извне, и файл, где он это делает. Не можешь назвать —
периметра нет.

## Формат пути

Цепочка звеньев «функция:строка → функция:строка», начинающаяся точкой входа
и заканчивающаяся уязвимой строкой; на каждом звене указывается имя
переменной, несущей внешнее значение:

`views.upload:31 (request.FILES["f"].name → name) → storage.save:12 (name → path) → storage.save:14 (open(path))`

Разрыв цепочки — звено, где значение переприсваивается константой,
валидируется или экранируется — закрывает находку.

## Опровержение

Узел `refutation` пытается сломать каждую гипотезу и обязан назвать ОДНО
из оснований:

- **A. Вход не внешний** — источник значения константа/конфиг.
- **B. Путь разорван** — валидация, приведение типа, белый список, ORM,
  параметризация, экранирование на пути.
- **C. Строка недостижима** — мёртвый код, ветка под выключенным флагом,
  функция без вызывающих.
- **D. Защита выше по стеку** — middleware, декоратор, модель валидации;
  указывается файл и строка защиты.
- **E. Опровергнуть не удалось** — путь воспроизводится, аргументы против
  не найдены.

Основание без ссылки на конкретную строку кода опровержением не считается:
«вероятно, где-то есть валидация» оставляет гипотезу в силе.

## Итоговый вес

| Состояние гипотезы | Вес |
|---|---|
| Путь выписан, опровержение E, класс 🔴p0 по [cwe.md](cwe.md) | 🔴p0 |
| Путь выписан, опровержение E, класс 🟠p1 | 🟠p1 |
| Путь выписан, но проходит через тестовый/административный код | 🟡p2 |
| Пути нет ИЛИ опровержение A–D | 🟢p3 |
| В элементе нет ни одной точки входа | 🟢p3 (все находки) |

Находка с основанием A–D не удаляется из отчёта: она переходит в 🟢p3 с
записанным опровержением. Удалённая находка теряется, понижённая —
проверяема при следующем прогоне.
