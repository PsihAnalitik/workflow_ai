# wiki: артефакты фабрики и wiki-apply (v1)

> ⚠ unverified: написано из знаний модели без внешнего материала —
> проверь факты при приёмке.

Как спека материализуется в файлы wiki: цепочка артефактов фабрики,
роль каждого узла и команда `wiki-apply`.

## Цепочка артефактов

```
input.xml → wiki_spec.xml → wiki_pages → wiki-apply → wiki/*.md
```

### 1. input.xml

Запрос пользователя с материалом целиком. Версионируется
артефакт-стором (`projects/wiki_maintainer/artifacts/input/vNN.xml`).
Содержит тему и полный текст исходного материала.

### 2. wiki_spec.xml

Спека — структура будущих страниц. Содержит:
- `<summary>` — что добавляется
- `<pages>` — перечень страниц с путями, purpose, source_chunks
- `<source_page>` (с v9) — путь к вербатим-исходнику
- `<source_request>` — исходный запрос вербатим
- `<index_updates>` — строки для index.md
- `<related>` — связи между страницами

### 3. wiki_pages

Артефакт, генерируемый LLM-узлом по спеке. Содержит готовое
содержимое каждой страницы в формате, пригодном для записи в .md
файлы. Проходит ревью (гейты) перед применением.

### 4. wiki-apply

Узел/CLI-команда, которая пишет артефакт `wiki_pages` в файловую
систему:
- Создаёт .md файлы страниц в соответствующих директориях `wiki/`
- Обновляет `index.md` затронутых директорий
- Материализует source-файлы из артефакта `wiki_spec.xml`
  детерминированно (минуя LLM)
- Пишет запись в `wiki/CHANGELOG.md`

Запуск: `uv run python -m workshop wiki-apply` с указанием прогона.

### wiki-render

Отдельная команда `uv run python -m workshop wiki-render`, которая
собирает HTML-витрину из .md файлов. Перед пересборкой каталог
`wiki_html` нужно удалить — рендерер не пишет поверх существующих
файлов.

## Где смотреть

- **Исходники:** `wiki/index.md` — входная точка, `wiki/CHANGELOG.md` —
  история изменений
- **HTML-витрина:** `wiki_html/index.html` — открывается в браузере
- **Артефакты:** `projects/wiki_maintainer/artifacts/` — полная
  трассировка «страница ← спека ← исходник»
