# wiki: no-op-спека (v1)

> ⚠ unverified: написано из знаний модели без внешнего материала —
> проверь факты при приёмке.

Сценарий, при котором агент `wiki_spec` распознаёт: запрос пользователя
уже полностью покрыт существующей страницей wiki. Вместо дублирования
агент выдаёт пустую спеку — no-op.

## Как работает

1. Агент читает существующую страницу через `wiki_get` (путь к странице
   вычисляется из темы запроса).
2. Сравнивает материал запроса с содержимым страницы.
3. Если покрытие полное — выдаёт спекус пустыми `<pages/>`
   и `<index_updates/>`, а в `<summary>` указывает путь покрывающей
   страницы.
4. Цепочка останавливается: wiki_pages не генерируется, wiki-apply
   получает reject.

## Правило W0 ревьюера

Добавлено в v8 цеха `wiki_maintainer` после бага с зацикливанием
ревьюера на пустых `<pages>`:

- При пустом `<pages>` постраничные проверки W2–W4 **неприменимы**.
- Проверяется только, что `<summary>` содержит путь к покрывающей
  странице и этот путь существует в дереве wiki.
- W3 переформулирован постранично (ранее был общим для всей спеки).

## output_format в wiki_spec.base.md

В `<output_format>` промпта `wiki_spec` узаконена no-op-форма:

- `<pages/>` — пустой элемент
- `<index_updates/>` — пустой элемент
- `<summary>` — содержит путь покрывающей страницы

## История

Обнаружено на тесте-ловушке: запрос «добавь страницу про SQL-запросы
к CSV/Parquet через duckdb» при уже существующей
`python/duckdb/files-sql.md`. Агент отработал корректно, но ревьюер
зациклился — правки v8 исправили это.
