# wiki: прожарка промптов — хорошие примеры (v1)

Учебный домен — универсальный ReAct-агент поверх витрины метрик (инструменты:
каталог показателей, карточка показателя, запрос данных, резолвер периодов).
Не является текущей задачей; показывает ФОРМУ. Измерения П1–П8 и severity —
[методология](../review.md); дефекты — [bad.md](bad.md); продвинутые приёмы —
[practices.md](practices.md).

## Правила агентного узла (ЕСЛИ→ТО, негативные случаи)

```xml
<rules>
- Каталог (list_indicators) и карточка (inspect_indicator) — МЕТАДАННЫЕ, а не данные
  ответа: получив карточку, ВЫЗОВИ инструмент данных; не финализируй на метаданных.
- ЕСЛИ инструмент вернул no_match/ошибку → исправь параметры по подсказке (hint)
  и повтори; НЕ повторяй тот же неверный вызов.
- ЕСЛИ обязательный контекст (период, категория метрики) не задан пользователем →
  задай уточняющий вопрос БЕЗ вызова инструмента; не подставляй умолчания.
- НЕ называй конкретное число, пока не получил его успешным вызовом инструмента.
</rules>
```

Почему это хорошо: каждое правило привязано к конкретному триггеру (no_match,
незаданный период) и несёт негативный случай («НЕ повторяй», «БЕЗ вызова»);
правил четыре — в лимите плотности П3; ни одного «старайся/по возможности».

## Описание инструмента (TRIGGER/SKIP + граничные примеры)

```xml
<resolve_comparison_period>
Календарные даты сравнительного периода. АППН = аналогичный период прошлой
НЕДЕЛИ (−1 неделя), АППГ = прошлого ГОДА (−1 год).
ЕСЛИ в запросе «АППН»/«АППГ»/«год к году» → ОБЯЗАТЕЛЬНО вызови этот инструмент
и используй ВОЗВРАЩЁННЫЕ им даты для обоих окон сравнения.
ЗАПРЕЩЕНО вычислять окно вручную (−7 дней / −1 год): даты АППН/АППГ календарно
скорректированы на праздники — ручная арифметика даёт НЕВЕРНЫЕ даты.
Резолвер ТОЛЬКО для АППН/АППГ; для «вчера»/«месяц назад» бери даты из зоны context.
  <examples>
  - НЕВЕРНО: «АППН недели 15–21 апреля» → взять 15–21 минус 7 дней вручную.
    ВЕРНО: resolve_comparison_period("2024-04-15","2024-04-21","appn").
  - «как изменилось vs месяц назад» → БЕЗ резолвера: даты из зоны context.
  </examples>
</resolve_comparison_period>
```

Почему это хорошо: TRIGGER — конкретный список маркеров в запросе, не «when
relevant»; SKIP явный и указывает альтернативу (зона context); анти-пример
показывает типичную ошибку модели, а не только счастливый путь (П5, П7).

## Процесс с явным режимом коллапса (судья-оценщик)

```xml
<process>
# отложенный коллапс: сначала полная таблица покрытия, решение — последним
Шаг 1. Выпиши из ТЗ все FR-id с acceptance-критериями. НЕ оценивай.
Шаг 2. Для КАЖДОГО FR найди модуль и тест; пометь covered/partial/missing.
       НЕ выноси решение, пока таблица не полна.
Шаг 3. Только после полной таблицы — решение READY/NOT_READY.
</process>
```

Почему это хорошо: поисковая задача (оценка покрытия) получает отложенный
коллапс — запрет на решение до полной таблицы удерживает суперпозицию (П6);
фазы пронумерованы, у каждой явный запрет преждевременного вывода.
