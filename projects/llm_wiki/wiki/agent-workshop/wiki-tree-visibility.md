# wiki: wiki-tree-visibility (v1)

Механизм, дающий ревьюеру цеха `wiki_pages` видимость реального
дерева wiki. Внедрён на сессии a06a07b9 (2026-07-10) вместо
обходного манёвра с копиями подстраниц.

## Проблема

Ревьюер не видел применённые ранее подстраницы — все ссылки
на них выглядели как «битые». Приходилось тащить в file map
прогона дословные копии подстраниц: правка одной строки
обходилась в 12 файлов. Обход работал стабильно, но был
хрупким и раздувал контекст.

## Решение

По принципу «код — следствие артефактов» обновлён `.grace/DevelopmentPlan.xml`
(TSK-1606 в M-16, шаг сборки промпта в M-06), затем код:

- **`workshop/wiki_loader.py`** — функция `tree_listing(root)`:
  собирает блок `=== wiki tree ===` с путями всех страниц wiki
  (без содержимого — контекст не раздувается). Несуществующий
  корень — явная ошибка, а не пустой листинг, чтобы опечатка
  в конфиге не превратила все ссылки в «битые».
- **`workshop/models.py`** — опциональное поле
  `NodeConfig.wiki_tree_root` (по умолчанию `None` — остальные
  узлы не затронуты).
- **`workshop/workshop_node.py`** — `build_prompt` включает
  блок `=== wiki tree ===` в INPUTS цеха.

## Результат

Обходной манёвр с копиями подстраниц отменён. Ревьюер видит
актуальное дерево wiki при каждом прогоне, ссылки проверяются
по реальному состоянию файловой системы.
