# wiki: рабочая таксономия CWE для Python-кода (v2)

Каталог цеха `code_auditor`. Не полный список CWE, а те классы, которые
статически различимы в Python-исходнике и встречаются в реальных
коммитах-исправлениях.

Вес — по шкале области (🔴p0 высший, обратна остальной вике). Вес класса из таблицы — ПОТОЛОК:
фактический вес находки определяется достижимостью
([reachability.md](reachability.md)), а не классом.

## Классы

- **C1 🔴p0 CWE-78 — инъекция команды ОС.** `subprocess` с `shell=True` и
  конкатенацией, `os.system`, `os.popen` от внешней строки.
  Не находка: аргументы списком без `shell=True`; строка — литерал.

- **C2 🔴p0 CWE-89 — SQL-инъекция.** f-строка/`%`/`+` внутри `execute`.
  Не находка: параметризованный вызов `execute(sql, params)`; имя таблицы
  из белого списка-константы.

- **C3 🔴p0 CWE-502 — небезопасная десериализация.** `pickle.loads`,
  `yaml.load` без `SafeLoader`, `marshal`, `dill` от недоверенных данных.
  Не находка: `yaml.safe_load`; pickle от файла, записанного самим процессом.

- **C4 🔴p0 CWE-22 — выход за каталог.** Склейка пути с внешним сегментом без
  нормализации и проверки корня.
  Не находка: `Path(root).resolve()` + проверка `is_relative_to`; сегмент
  сверен с белым списком. Одного `os.path.join` для находки НЕДОСТАТОЧНО.

- **C5 🟠p1 CWE-79 — XSS.** Рендер без экранирования: `mark_safe`,
  `|safe`, `Markup`, ручная сборка HTML из внешней строки.
  Не находка: автоэкранирование шаблонизатора не отключено.

- **C6 🟠p1 CWE-918 — SSRF.** HTTP-запрос по URL, пришедшему извне, без
  проверки схемы и хоста.

- **C7 🔴p0 CWE-798 / CWE-259 — секрет в коде.** Литеральный токен, пароль,
  ключ. Не находка: значение из `os.getenv`/настроек; плейсхолдер в примере
  или тесте (`"changeme"`, `"xxx"`).

- **C8 🟠p1 CWE-327 / CWE-330 — слабая криптография и случайность.** `md5`,
  `sha1` для подписи или паролей, `random` для токенов и секретов.
  Не находка: `md5` как некриптографический хэш для кэш-ключа при явном
  `usedforsecurity=False` или очевидном контексте кэша.

- **C9 🟠p1 CWE-295 / CWE-319 — отключённая проверка TLS.** `verify=False`,
  `ssl._create_unverified_context`, `http://` к внешнему API.

- **C10 🟡p2 CWE-209 — утечка в сообщении об ошибке.** Traceback,
  SQL-запрос, путь файловой системы в ответе пользователю.

- **C11 🟠p1 CWE-863 / CWE-862 — отсутствующая или неверная авторизация.**
  Обработчик, меняющий чужой объект по идентификатору из запроса без
  проверки владельца.

- **C12 🟠p1 CWE-400 — неограниченное потребление ресурсов.** Чтение тела
  запроса или файла целиком без лимита, `re` с катастрофическим бэктрекингом
  по внешней строке.

## Типичные ложные срабатывания

- **Тест или фикстура.** Файл `tests/`, `conftest.py`, `*_test.py`: секрет,
  `verify=False` и `shell=True` там — обстановка стенда. Вес не выше 🟡p2.
- **Вход не внешний.** Строка собрана из констант модуля, аргументов CLI
  администратора, значений из собственного конфига. Это не «недоверенный
  ввод» (см. [reachability.md](reachability.md)).
- **Защита выше по стеку, а не рядом.** Валидация в middleware, в
  Pydantic-модели, в декораторе. Отсутствие проверки В СТРОКЕ находкой не
  является — искать, есть ли она на пути.
- **Мёртвый код.** Функция без вызывающих в пакете — вес понижается,
  находка не снимается.

## Формат находки

К общему формату (`id`, `класс`, `вес`, `локация`, `цитата`, `обоснование`)
добавляются: `cwe` (идентификатор CWE-NNN), `путь_достижимости` (см.
[reachability.md](reachability.md)), `предлагаемая_проверка` (описание теста,
воспроизводящего условие), `TH-id` модели угроз либо пометка
`вне_модели_угроз`.
